# T003 · TranscriptTimeline 검증

> 대상 프로덕션 클래스: `TranscriptTimeline`. 상태: 구현 전 · 모든 실행 미검증. 문서 생성은 테스트 통과가 아니다.

## 재현 준비

- [구현 TASK](../T003-TranscriptTimeline.md)와 [Checklist](../Checklist/T003-TranscriptTimeline.checklist.md)의 승인·선행 조건을 먼저 확인한다.
- 테스트 전용 세션 S1/S2, 평가자 A/B, 고정 루브릭·검수 전사 version을 사용한다. 실사용 원본을 변경하지 않는다.
- 기기/OS/앱/SDK/서버/모델 버전, 데이터 hash, 네트워크, 모드(live/cache/prepared), 시작·종료 시간을 기록한다.
- mock 단위 결과와 실제 API·실기기 결과를 별도 행으로 남긴다. 이 문서는 실행 절차이며 아직 실행하지 않았다.

## 측정과 판정

- 상태·권한·ID/시간 경계는 fixture의 기대값과 정확히 대조한다. 예외를 성공 상태로 바꾸지 않았는지 확인한다.
- 시간 측정이 관련되면 해당 구간의 monotonic clock을 사용한다. 전체 구성 명세의 목표와 실제 p50/p95·최댓값·실패율을 구분한다.
- 실기기/모델/네트워크가 없으면 해당 사례는 미검증으로 남긴다. mock 결과로 대체 통과시키지 않는다.
- 문제 발생 시 요구/환경 → 입력/구현 → 의존/반례의 세 관점에서 조건을 바꿔 확인한다. 동일 호출 반복을 재검증으로 세지 않는다.
