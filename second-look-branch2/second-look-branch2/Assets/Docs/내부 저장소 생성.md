# 내부 저장소 생성

웹에서 승인한 면접 요약과 평가 요약을 지원자·면접 차수별로 다시 조회할 수 있게 하는 서버 저장소 설계다. [면접 지원 기능 명세 F14](SECOND_LOOK_면접지원_기능명세.md)의 저장·권한 계약을 구체화한다.

## 저장할 기록

| 기록 | 필수 내용 |
| --- | --- |
| 면접 요약 | 지원자 ID, 면접 차수 ID, 질문·답변 요점, 한계와 열린 질문, 원문 근거 참조 |
| 평가 요약 | 같은 지원자·차수 ID, 작성한 평가자, 적용한 평가 기준 버전, 사람이 확정한 소견과 근거, 확인 상태 |
| 근거 참조 | 해당 지원자·차수, 전사 버전, 질문·발화 ID, 음성 구간 시작·종료 시각 |
| 승인·개정 내역 | 개정 번호, 작성자, 생성 시각, 근거를 확인한 승인자와 승인 시각, 개정 사유, 이전 승인본 참조 |

서버의 면접 차수 ID에 지원자를 연결하고 표시 이름은 화면에만 쓴다. 면접 요약과 평가 요약은 같은 지원자·차수 아래 별도 기록으로 관리한다. 요약에 원음이나 전체 전사를 복제하지 않고 저장된 원문을 참조한다. 같은 질문 비교가 이관 자료에 포함되면 1차와 2차 각각의 차수·질문·발화 참조를 보존한다.

## 저장과 권한

1. 웹에서 초안을 작성하거나 AI 제안을 불러온다. 내부 승인본 조회에는 초안이 노출되지 않는다.
2. 차수에 배정된 권한 있는 담당자가 웹에서 내용을 검토하고 승인한다. 서버는 요청자·지원자·차수·참조 범위를 검증하고 승인본, 근거 참조, 이력을 원자적으로 저장한다.
3. 웹은 권한이 있는 사용자에게만 현재 승인본과 필요한 근거를 표시한다. 개정은 새 버전으로 작성하고 승인된 이전 이력은 추적할 수 있게 한다. 동일 요청 재시도에서 중복 승인본이 생기지 않아야 한다.
4. 다음 면접관은 자신에게 배정된 이관의 승인 항목과 연결된 근거만 열 수 있다. 승인된 AR 표시용 요점과 질문은 서버가 권한과 차수를 확인한 뒤 제공한다.

조회 목록, 요약 상세, 승인, 이력, 원음 재생·다운로드 모두 같은 서버 권한 검사를 적용한다. 권한이 명시되지 않은 접근은 거부하며, 감사 기록에는 행위자·시각·대상·결과를 남긴다. 외부 AI 전달은 해당 범위의 별도 동의를 확인하는 경로로 처리한다. [OWASP 권한 검증 가이드](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)

## 저장 위치와 검증

현장 PC의 웹 서버 저장소를 초기 기준으로 한다. SQLite를 사용하는 경우 지원자·차수·요약 버전·원문 참조의 무결성을 외래 키로 확인하고, 저장 경로는 공유되는 소스 트리에서 분리한다. 운영 보관 기간과 승인 역할은 실제 데이터 사용 전에 정한다. [SQLite 외래 키 문서](https://www.sqlite.org/foreignkeys.html)

- [ ] 같은 지원자의 1·2차와 다른 지원자의 동일 차수를 각각 저장하고 조회 범위가 섞이지 않는지 확인한다.
- [ ] 다른 사람 ID·차수 ID·발화 ID를 지정해도 승인·조회·음성 재생이 거부되는지 확인한다.
- [ ] 미승인 또는 개정 중인 내용이 이관·AR·승인 목록에 노출되지 않는지 확인한다.
- [ ] 서버 재시작 후 승인본·근거·개정 이력을 읽고, 이중 승인 요청과 저장 실패가 중복·부분 저장을 만들지 않는지 확인한다.
- [ ] 배정된 2차 면접관이 승인 질문과 연결된 1차 음성만 확인할 수 있고, 권한 철회 이후에는 다시 조회할 수 없는지 확인한다.

현재 합성 시연 DB는 데모 세션의 관점·이관 결과를 보관한다. 이 문서의 지원자·차수별 내부 저장소와 접근 검증은 구현 후 별도로 확인한다.
