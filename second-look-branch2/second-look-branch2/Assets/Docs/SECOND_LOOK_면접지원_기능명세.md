# SECOND LOOK · 면접 지원 기능 명세

브랜치2의 면접 지원 기능 범위와 완료 기준이다. 기존 Android·서버 구조와 세부 클래스 계약은 [전체 구성 검토안](SECOND_LOOK_전체구성_검토안.md)을 참고한다. 화면과 데이터의 흐름은 이 문서의 정의를 따른다.

## 사용 흐름

1. **1차 면접과 공동 검토** — 평가자 A·B가 같은 면접을 보고 각각 근거와 해석을 남긴다. 면접관은 대화 중 현재 질문과 사용 가능한 답변 기록으로 AI 후속 질문을 받아, 다음 질문을 하기 전에 화면에서 선택할 수 있다. 두 사람의 확정 뒤 웹에서 함께 검토한다. 평가자마다 잘 포착한 서로 다른 발화와 그 근거를 나란히 보여준다.
2. **2차 면접 준비** — AI가 긴 답변의 요점을 정리하고, 면접관의 전문 분야 밖에서도 검증 기준을 잡을 수 있도록 후속 질문을 제안한다. 담당 면접관은 원문과 음성을 대조해 질문의 문구·의도·근거를 검토하고 이관할 항목을 확정한다.
3. **2차 면접 실행** — 배정된 면접관 C는 면접 전 웹에서 승인된 질문과 근거를 열고, 연결된 1차 음성 구간을 먼저 듣는다. 면접 중 글래스에서 질문이나 핵심 요약을 확인하며 대화를 이어 간다. 면접 뒤 웹에서 답변과 확인 결과를 기록한다.
4. **차수 간 비교와 내부 보관** — 두 차수에서 확인한 동일 질문 또는 의미와 조건이 대응하는 동일 쟁점의 답변을 원문과 함께 비교한다. 승인된 면접 요약과 평가 요약을 지원자·면접 차수별로 보관한다.

## F07 · 같은 차수의 관점과 다른 근거

- 공동 공개가 완료되면 웹에서 **평가자별 관점, 포착한 발화, 잘 포착한 이유, 다른 답변의 보완 근거와 한계**를 확인한다. 서로 다른 좋은 근거는 하나의 결론으로 합치지 않고 각각의 원문과 맥락을 남긴다.
- AI 요약은 면접 상황·질문 의도·해당 면접관의 관심 기준을 반영한다. 각 요점에는 원문 발화 ID와 음성 시작·종료 시각을 연결한다. 공통 사실, 평가자별 해석, 추가 확인 사항을 구분한다.
- 웹에 제안 상태와 근거를 먼저 보여준다. 사람이 선택하거나 수정한 짧은 요점은 AR에 표시해 대면 공동 검토 중 활용한다.

## F12 · 긴 답변 요약과 전문 후속 질문

- 긴 답변에서 **무엇을 했는지, 어떤 근거로 판단했는지, 어떤 결과와 한계를 말했는지** 요약한다. 발화에서 확인되는 사실과 해석 또는 검증할 점을 구분하고, 핵심 조건·수치·불확실성은 원문과 같은 의미로 남긴다.
- 전문 후속 질문은 직무·과제·답변의 맥락을 이용한다. 질문마다 **쉽게 읽을 문장, 왜 묻는지, 답변에서 구체적으로 확인할 점, 연결한 원문과 시간**을 제공한다. 평가자는 질문의 내용 또는 전문 용어를 웹에서 확인하고 수정할 수 있다.
- 진행 중인 면접에서는 이미 웹에 기록된 답변이나 검토 가능한 사전 자료를 사용한다. AI 요점과 후속 질문 제안을 면접관이 웹에서 확인하고, 말하기 전에 필요한 항목을 선택해 글래스에 띄울 수 있다.
- 길이로 답변을 평가하지 않는다. 기술적 사실이나 수치, 지원자가 말한 경험을 새로 지어내지 않는다. 검증할 근거가 없으면 `확인 필요`로 남겨 면접관에게 알린다.
- 구조화된 AI 출력은 형식·권한·지원자·차수·원문 버전에 맞는지 서버에서 검증한다. 원문 인용은 서버가 보관한 자료를 사용한다. 질문의 타당성과 전문성은 담당 면접관이 확인한다. [Gemini 구조화 출력 공식 문서](https://ai.google.dev/gemini-api/docs/structured-output)

## F11·F13 · 승인된 질문 이관과 같은 질문 비교

| 용도 | 넘길 내용 | 2차 면접 결과 |
| --- | --- | --- |
| 전문 검증 | 질문, 확인 목적, 답변에서 검증할 조건·방법·수치, 1차 발화와 음성 구간 | C가 질문 사용 여부와 답변 요지, 추가 확인 필요 여부를 남긴다. |
| 같은 질문의 일관성 확인 | 1차 질문과 답변, 원문 ID와 시간, 2차에서 확인할 동일 쟁점 | 웹에서 두 차수의 질문·답변·원문을 나란히 보여주고 공통점, 차이, 질문 조건·맥락 차이, 확인이 필요한 부분을 기록한다. |

- 이관은 해당 지원자의 1차·2차 세션을 연결한다. 승인된 질문만 수신자 C에게 공개하며 승인자, 문구, 근거, 승인 시점과 후속 상태를 추적한다.
- 1차 음성을 웹에서 문제의 구간부터 재생한다. C는 텍스트 요약, 질문 의도, 원래 답변을 면접 전에 확인하고, 면접 중 AR에서 자신에게 배정된 질문을 열 수 있다.
- 비교 결과의 용도는 사실관계와 맥락을 더 확인하는 것이다. 차이 또는 누락을 거짓말·정직성·인성의 지표로 해석하지 않는다. AI는 일관성 점수, 지원자 순위, 합격 여부를 생성하지 않는다.
- 같은 평가 기준만으로는 질문을 연결할 수 없다. 짝을 지은 경우 두 차수의 질문과 원문 버전·발화·시간을 각각 보존한다. 두 차수의 질문이나 맥락이 충분히 대응하지 않으면 `같은 질문으로 비교할 근거 부족`을 표시한다. 일부 답변의 누락 또는 기록하지 못한 구간은 그 상태를 표시한다.

## F09 · 웹·서버와 AR의 역할

| 구성 | 역할 |
| --- | --- |
| 웹·서버 | 지원자·차수·권한·원문·음성·질문·승인 상태의 기준이다. 수정, 원문 검토, 질문 승인, 결과 저장, 기록 조회는 여기에서 이뤄진다. |
| Android 연동 앱 | 현재 사용자와 배정된 차수로 승인된 화면용 요점을 조회한다. Hi Rokid와 CXR-L을 통해 글래스 화면 세션을 열고 한 번에 필요한 정보만 표시한다. |
| 디스플레이형 웨이브가이드 Rokid Glasses | 면접관이 대면 대화 중 시선을 오래 떼지 않고 볼 핵심 질문, 같은 차수의 상황·면접관 기준별 핵심 요점, 다음 확인 항목을 짧게 보여준다. 실제 렌즈 표시는 기능 완료 조건이다. |

AR에 실시간 전사나 스크롤되는 전체 답변을 표시하지 않는다. 웹에 기록된 원문에서 추출·검토한 요점과 승인된 질문을 현재 세션에 맞춰 갱신한다. 참여자나 차수가 바뀌거나 권한 또는 연결이 만료되면 이전 표시를 지운다. 연결 실패를 웹에서 알리고 질문·근거는 웹에서 계속 확인할 수 있게 한다.

사용자가 휴대폰 Hi Rokid에서 글래스 연결을 확인했다. CXR-L Custom View 실행과 실제 렌즈의 한글 표시는 아직 검증하지 않았다.

Rokid 공식 문서는 CXR-L이 휴대폰 앱과 Hi Rokid를 연결하고 `Custom View`에서 화면을 열고 갱신하고 닫는 경로를 설명한다. SDK 세션 준비와 실제 표시는 별도로 확인한다. 기기 모델·펌웨어·Android·Hi Rokid·SDK 버전, 권한, 한글 가독성, 갱신·닫기, 재연결 시 기존 표시 제거를 동일 장비 조합에서 기록한다. [Rokid 공식 CXR-L 가이드](https://kr.rokid.com/43)

## F14 · 내부 요약·평가 요약 보관

저장 구조와 접근 검증 항목은 [내부 저장소 생성](<내부 저장소 생성.md>)에 정의한다.

- 지원자와 면접 차수를 키로 **승인된 면접 요약**과 **승인된 평가 요약**을 따로 보관한다. 면접 요약에는 답변 핵심·근거·남은 질문을, 평가 요약에는 담당 평가자가 작성·확정한 평가 기준별 소견·근거·확인 상태를 담는다.
- 요약 레코드에서 지원자 ID, 차수, 원문 버전·발화 참조, 작성자·승인자·승인 시점, 승인 상태 및 개정 이력을 조회할 수 있어야 한다. 수정 시 이전 승인본과 누가 무엇을 바꿨는지 추적할 수 있게 한다.
- 배정 또는 별도 조회 권한이 확인된 내부 사용자만 해당 자료에 접근한다. 배정된 2차 면접관에게는 이관 목적에 필요한 승인 자료를 공개한다. 다른 지원자·면접 차수의 원문과 요약, 공동 공개 전 다른 평가자의 개인 기록은 서버에서 접근을 차단한다.

## 검증 기준과 현재 상태

| 검증 | 통과에 필요한 관측 |
| --- | --- |
| 원문과 요약 | 길이가 긴 답변의 확인된 수치·조건·한계를 요약에서 유지하고, 요점별 원문 및 시간 구간을 열고 들을 수 있다. 잘못된 지원자·차수·발화 ID를 거부한다. |
| 같은 차수 검토 | 각 평가자의 서로 다른 유효 근거를 비교하고, 면접관 기준에 맞춘 요점을 웹에서 검토해 AR에 표시한다. |
| 전문 질문과 이관 | 진행 중인 면접에서 다음 질문을 하기 전에 제안을 검토·선택할 수 있고, 이관 때는 승인한 전문 질문만 C에게 보인다. C가 1차 원음의 지정 구간을 듣고 질문을 사용한 뒤 답변과 확인 상태를 남긴다. |
| 같은 질문 비교 | 같은 질문에 대한 이전·이후 답변과 출처, 조건 차이가 함께 표시된다. 짝이 없는 경우 확인할 근거가 부족하다고 표시한다. |
| 보관·권한 | 내부 권한이 있는 사용자는 승인 요약과 평가 요약을 지원자·차수별로 다시 열 수 있다. 미승인·타 지원자 자료 조회는 차단된다. |
| 실기기 | 대상 조합에서 실제 렌즈로 한글 질문과 요점을 확인하고, 차수 변경·연결 종료·권한 만료에서 이전 화면이 지워진다. |

현재 브랜치2의 웹에는 기존 면접관 대시보드와 로컬 합성 면접 시연의 **원음 재생, 근거 그래프, 질문 이관** 탭이 있다. 합성 면접 시연은 별도의 데이터로 실행한다. 여기에서 보여주는 브라우저 HUD는 향후 실기기 표시의 시안이다. 전문 후속 질문 생성·검증, 차수 간 같은 질문 비교, 내부 승인 요약 보관 및 권한 검증, Android/Rokid 실기기 완료 여부는 위 기준으로 각각 확인해야 한다.
